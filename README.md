# Секретарь-помощник

Учебное русскоязычное веб-приложение для голосовой записи на 30-минутные встречи. Приложение использует раздельный каскад: браузерный микрофон → файловый STT → LLM → проверка и запись на клиенте → поток текста → файловый TTS.

## Локальный запуск

Требуется Node.js 20.9 или новее.

1. Установите зависимости:

   ```powershell
   npm install
   ```

2. Создайте `.env.local` и укажите серверный ключ (файл уже исключён из Git):

   ```text
   PROXYAPI_API_KEY=ваш_ключ_ProxyAPI
   ```

   Если ключ выдан в `proxyApiKey.txt`, скопируйте только его значение. Не переименовывайте переменную в `NEXT_PUBLIC_*`: ключ не должен попадать в браузер.

3. Запустите приложение:

   ```powershell
   npm run dev
   ```

4. Откройте [http://localhost:3000](http://localhost:3000). Микрофон будет запрошен только после нажатия «Начать разговор».

Production-проверка:

```powershell
npm run typecheck
npm test
npm run build
npm start
```

## Модели и API

- STT: `x-ai/grok-stt-2.0`, `POST /v1/audio/transcriptions`, русский язык. Модель можно переопределить через `STT_MODEL`.
- Интерпретация и ответ: `openai/gpt-5-mini`, `POST /v1/responses`; финальный ответ передаётся потоком.
- TTS: `openai/gpt-4o-mini-tts`, голос `alloy`, `POST /v1/audio/speech`.

Все обращения к ProxyAPI выполняются серверными route handlers. Браузер ключ не получает. Аудиофрагмент ограничен 8 МБ, тексты и история также имеют серверные пределы.

## Как устроена запись

Расписание работает по локальному времени браузера: понедельник–пятница, 09:00–18:00, последнее начало в 17:30. При первом открытии один раз создаются демонстрационные занятые слоты текущей и следующей недели. Документ `voice-secretary.schedule.v1` хранится в `localStorage` и содержит версию, ISO-время, длительность, тип и идентификатор каждой записи.

LLM только предлагает структурированное действие. Во время разговора клиент проверяет дату, рабочие часы, прошлое время и занятость, но хранит единственный выбранный слот только в памяти сессии: каждое новое время заменяет предыдущий выбор и не блокирует расписание. При голосовом прощании слот повторно проверяется по актуальному `localStorage`, сохраняется одним действием и повторно читается из хранилища. Ручное завершение разговора отбрасывает неподтверждённый выбор.

Данные принадлежат одному браузеру и устройству. Это не общий публичный календарь, между вкладками и устройствами синхронизации нет.

## Голос и перебивание

Два независимых `MediaRecorder` выполняют разные задачи: короткий рекордер каждые 800 мс создаёт самостоятельный WebM-файл для быстрого чернового распознавания, а второй непрерывно хранит всю реплику для окончательного STT. При старте детектор кратко калибрует микрофон, отбрасывает невозможные по длине черновики из тишины и завершает реплику примерно после 1,2 секунды тишины, позволяя делать естественные паузы внутри фразы. TTS говорит в ускоренном разговорном темпе; следующие фразы синтезируются заранее и проигрываются строго по порядку. Это согласованная имитация постепенного STT/TTS, не настоящий потоковый speech API.

При выборе времени подтверждение формируется локально как «Выбрано…», но запись ещё не считается сохранённой. При прощании выбранный слот фиксируется и помощник произносит только «До свидания!», без повторения условий. Для вопросов, отказов и уточнений потоковый текст LLM отображается по мере поступления. Законченные фразы отдельно отправляются в TTS и проигрываются последовательно; каждый TTS-ответ — готовый MP3-файл целиком. Автоматическое перебивание голосом включается только во время воспроизведения ответа, чтобы шум не отменял запрос на стадии размышления; кнопка «Перебить и говорить» остаётся доступна и во время генерации. При первом признаке голоса запускается предварительный рекордер: после подтверждения речи он без перезапуска становится основным и сохраняет начало перебивающей реплики, а при шуме буфер отбрасывается. Поздние данные от старого `turnId` отбрасываются.

Автоматический VAD использует порог громкости, а не семантическое распознавание. С динамиками возможны ложные срабатывания от эха, поэтому для надёжной проверки рекомендуются наушники и всегда доступна ручная кнопка.

После успешной записи разговор остаётся активным: пользователь может назвать другое время или задать вопрос. Явная финальная реплика — например, «всё, спасибо», «до свидания» или «пока» — распознаётся как завершение. Помощник напоминает о сохранённой встрече, прощается, освобождает микрофон и автоматически показывает итог сессии.

## Ручная проверка

1. До старта убедитесь, что индикатор микрофона браузера выключен. Начните разговор, разрешите микрофон, затем завершите разговор и проверьте, что индикатор погас.
2. Скажите: «Запиши меня завтра в 17:00». Проверьте отдельные черновой и окончательный тексты, постепенный ответ и занятый слот после подтверждения.
3. Запросите демонстрационно занятый слот (понедельник 10:00, среда 13:00 или пятница 16:00), выходной, 18:00 и прошедшее время. Успешной записи быть не должно; ответ должен содержать до трёх альтернатив.
4. Скажите неоднозначно: «После обеда». Помощник должен уточнить время и не записывать слот.
5. После успешной записи скажите: «Нет, перенеси на четверг в 15:30». При свободном времени старая запись должна атомарно замениться.
6. Во время ответа заговорите снова, а затем повторите тест ручной кнопкой. Старый звук должен остановиться сразу, прерванный текст — получить пометку, поздние события не должны создать запись.
7. Обновите страницу: пользовательская запись должна сохраниться. Начните новый разговор: история должна быть чистой, расписание — прежним.
8. Для проверки ошибок временно уберите ключ, запретите микрофон или отключите сеть. Интерфейс не должен показывать ложное подтверждение и должен предложить повтор.
9. Проверьте ширины около 390 и 1440 px, горизонтальное переключение дней, Tab/Enter и режим уменьшенной анимации.

Для сценариев без микрофона во время активной сессии предусмотрено текстовое поле. Оно проходит тот же LLM- и booking-конвейер и удобно для бизнес-проверок, но не заменяет голосовой приёмочный тест.

## Vercel

Импортируйте репозиторий как Next.js-проект и добавьте `PROXYAPI_API_KEY` в Project Settings → Environment Variables для нужных окружений. Серверные маршруты не хранят расписание; после деплоя оно по-прежнему локально для каждого браузера. Проверьте лимиты длительности функций и размера тела в выбранном тарифе Vercel.
